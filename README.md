# cdk: serverless products on GCP

A monorepo for products made of **apps (frontends), APIs, jobs, workers
and functions** on Cloud Run. Each product is a folder
with one subfolder per component, holding its code and a `deployment.yml` (memory, scaling,
networking, health checks, permissions). Everything else (Terraform, Atlantis,
Drone, release, linting, ownership) is shared at the root and run by the `cdk` CLI.

```bash
mise install && mise run setup        # once: pinned toolchain, deps, git hooks
```

```bash
cdk new orders                        # interactive: pick apps / apis / jobs / workers / functions
```

## Layout

```
products/<product>/              ← product teams (CODEOWNERS: their team)
  apps/<name>/  apis/<name>/     one folder per component: code, Dockerfile, lockfile,
  jobs/<name>/  workers/<name>/  and deployment.yml (runtime config, schema per type)
  functions/<name>/
  deploy/                        generated: Terraform root + <env>.tfvars.json (Atlantis runs here)

platform/                        ← platform team
  terraform/modules/             product → service / job / worker-pool / function, naming, identity
  templates/components/          nextjs, react, fastapi, python-job, python-worker, python-function
  schema/                        generated; editor autocomplete + validation (product, app, api, job, worker, function)
  ci/atlantis/repos.yaml         server-side Atlantis workflow

tools/cdk/                       the CLI (uv package, tested)
platform.yaml                    org, team, labels, region, registry, deployers, per-env state bucket + VPC

mise.toml                        toolchain versions + tasks (setup, fmt, lint, test, check)
pyproject.toml  uv.lock          uv workspace: cdk + ruff, basedpyright, pytest config
package.json  pnpm-workspace.yaml  biome.json
lefthook.yml                     git hooks    renovate.json   dependency update PRs
.drone.yml                       one pipeline for all products
atlantis.yaml  CODEOWNERS  pyrightconfig.json   generated by `cdk sync`
```

## Everyday commands

| | |
|---|---|
| `cdk add orders api search` | new component: creates `apis/search/` (code + deployment.yml) from the template, locks deps |
| `cdk config orders/search --env prod` | the effective deployment.yml for an env |
| `cdk remove orders reconcile` | remove component (and its folder) |
| `cdk sync` | regenerate generated files (the pre-commit hook does it for you) |
| `cdk check --affected` | lint, type-check, test only what your branch changed |
| `cdk affected` | list components your branch touches |
| `cdk release dev --dry-run` | show what a release would build and deploy |
| `mise run fmt` / `lint` / `test` / `check` | whole-repo tasks; `check` is what CI runs |

## How changes flow

```
edit deployment.yml ─► PR ─► Atlantis plans <product>-<env> ─► approve ─► atlantis apply
edit component code ─► PR ─► CI checks affected components ─► merge ─► `cdk release dev`
drone promote <build> prod ─► `cdk promote dev prod` (the exact images running in dev)
```

Terraform ignores container images, so infra applies and code releases never
overwrite each other.
