# deployment.yml reference

Every component is a folder with its code and a `deployment.yml`:

```
products/orders/
  product.yaml                     product-level: team, envs, region
  apps/storefront/deployment.yml   ┐
  apis/backend/deployment.yml      │  one per component; the folder it sits in
  jobs/nightly-export/...          │  (apps, apis, jobs, workers, functions)
  workers/email-sender/...         │  decides the Cloud Run type
  functions/gcs-ingest/...         ┘
  deploy/                          generated by `cdk sync`
```

* **The folder is the registry.** A component exists if `<section>/<name>/deployment.yml` exists.
  `cdk add` creates it from a template; `cdk remove` deletes the folder.
* **Each type has its own schema** (`platform/schema/<type>.schema.json`), limited to what that
  Cloud Run resource supports. VS Code autocompletes and validates as you type, and `cdk` rejects
  unknown keys with a list of the allowed ones.
* **Every key is optional.** Anything you leave out uses the default shown below.
* `cdk config orders/backend --env prod` prints the effective config for an env.

## Where each block applies

| Block | app | api | job | worker | function |
|---|:-:|:-:|:-:|:-:|:-:|
| `container` (port, command, args) | ✓ | ✓ | command/args | command/args | |
| `resources` (cpu, memory) | ✓ +cpu_idle, startup_cpu_boost | ✓ +cpu_idle, startup_cpu_boost | ✓ | ✓ | ✓ |
| `scaling` | min/max/concurrency | min/max/concurrency | | instances | min/max/concurrency |
| `timeout` (request) | ✓ | ✓ | | | ✓ |
| `execution` (tasks, retries, task_timeout) | | | ✓ | | |
| `schedules` | | | ✓ | | |
| `triggers` | | | | | ✓ |
| `network.ingress` | ✓ | ✓ | | | ✓ |
| `network.egress` | ✓ | ✓ | ✓ | ✓ | ✓ |
| `health` (startup, liveness) | ✓ | ✓ | | ✓ | |
| `session_affinity` | ✓ | ✓ | | | |
| `execution_environment` | ✓ | ✓ | ✓ | | |
| `env`, `permissions`, `calls`, `environments` | ✓ | ✓ | ✓ | ✓ | ✓ |
| `permissions.public`, `permissions.invokers` | ✓ | ✓ | | | ✓ |

## Full example (api)

```yaml
# yaml-language-server: $schema=../../../../platform/schema/api.schema.json
template: fastapi

container:
  port: 8080                  # default 8080
  command: [uvicorn]          # default: the image's ENTRYPOINT/CMD
  args: [main:app]

resources:
  cpu: "1"                    # "1" | "2" | "4" | "8"; services may use "0.5"
  memory: 512Mi               # default 512Mi
  cpu_idle: true              # default true: CPU only while handling requests
  startup_cpu_boost: false    # extra CPU during startup

scaling:
  min_instances: 0            # default 0 (scale to zero)
  max_instances: 10           # default 10
  concurrency: 80             # requests per instance; default 80 (functions: 1)

timeout: 300s                 # request timeout, default 300s
session_affinity: false
execution_environment: gen2   # gen1 | gen2; default: Cloud Run decides

network:
  ingress: internal           # internal (default) | load-balancer | all
  egress: private-ranges      # private-ranges (default) | all-traffic | none (no VPC)

health:
  startup:  { http: /healthz, period: 5s, failure_threshold: 10 }
  liveness: { http: /healthz, period: 30s }
  # without `http` it's a TCP check; also: port, initial_delay, timeout

env:
  LOG_LEVEL: info
  DB_URL: { secret: orders-db-url }                 # version: latest
  API_KEY: { secret: projects/shared/secrets/key, version: 3 }

permissions:                  # IAM for this component's own service account
  public: false               # true = allUsers may invoke (needs ingress all / load-balancer)
  invokers: [nightly-export, "group:ops@acme.com"]
  secrets: [extra-secret]     # env secrets are granted automatically
  buckets: { "acme-orders-uploads-{env}": write }   # read | write | admin
  publish: [orders-events]
  subscribe: [orders-requests]
  bigquery_datasets: { orders_analytics: read }     # read | write; "project:dataset" ok
  project_roles: []           # escape hatch, needs a reason in review

calls: [search]               # invoke another app/api/function: grants run.invoker, sets SEARCH_URL

environments:                 # per env, deep-merged over the above (lists are replaced)
  prod:
    scaling: { min_instances: 2, max_instances: 30 }
    env: { LOG_LEVEL: warning }
```

## Type-specific blocks

**job**

```yaml
execution:
  tasks: 4                    # default 1; each task gets CLOUD_RUN_TASK_INDEX
  parallelism: 2              # default 0 = all at once
  max_retries: 3              # per failed task, default 3
  task_timeout: 600s          # default 600s
schedules:
  nightly: { cron: "0 2 * * *", time_zone: Europe/Berlin }
  weekly:  { cron: "0 4 * * 0", args: [--full], paused: false }
```

**worker**

```yaml
scaling:
  instances: 2                # always-on instances, default 1
health:
  liveness: { http: /healthz, port: 8080 }   # workers have no serving port; set one for checks
```

**function**

```yaml
triggers:
  upload:
    event_type: google.cloud.storage.object.v1.finalized
    filters: { bucket: "acme-orders-inbox-{env}" }
  events:
    event_type: google.cloud.pubsub.topic.v1.messagePublished
    pubsub_topic: "projects/{project}/topics/orders-events"
```

## Placeholders

`{env}`, `{project}` and `{product}` are filled in anywhere: bucket names, env values, topics.

## Environment variables you always get

`ENV`, `PRODUCT`, `COMPONENT`, plus `<NAME>_URL` for each entry in `calls`.

## How it reaches Cloud Run

```
deployment.yml ─┐
product.yaml   ─┼─ cdk sync ─► deploy/<env>.tfvars.json ─► Atlantis plan/apply ─► Cloud Run
platform.yaml  ─┘   (validated, env-merged)    (committed: the PR diff shows the exact effect per env)
```

The pre-commit hook runs `cdk sync` for you, and CI fails if the generated files are stale.
CI also plans every product env against a mocked provider (`deploy/tests/plan.tftest.hcl`).

A change to `deployment.yml` alone is infra, so it goes through Atlantis. It doesn't
rebuild or redeploy the image. Code changes are released by Drone.

## product.yaml

```yaml
product: orders            # 2-10 chars, [a-z][a-z0-9]*, prefixes every resource and SA name
team: commerce             # GitHub team slug: CODEOWNERS + labels
envs: [dev, prod]          # subset of platform.yaml envs
region: europe-west1       # optional, default platform.yaml region
projects: { dev: legacy-orders-dev }   # optional, default {org}-{product}-{env}
labels: { cost-center: cc-123 }        # optional, on every resource
```
